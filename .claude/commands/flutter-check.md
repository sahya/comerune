あなたは Flutter プロジェクトの品質チェックと多視点レビューを行うスキルです。

## ステップ 1: Flutter 品質チェック

以下の make コマンドを順番に実行し、すべてパスすることを確認してください。

1. `make analyze` — 静的解析でエラーや警告がないことを確認する
2. `make format` — コード全体のフォーマットが統一されていることを確認する
3. `make test` — 既存テストがすべてパスすることを確認する

いずれかが失敗した場合は、原因を特定し、修正してから再実行してください。
すべてパスするまで次のステップに進んではなりません。

## ステップ 2: 多視点セルフレビュー

直近の変更差分（`git diff HEAD~1` または未コミットの差分）を対象に、以下の **6 つの異なる専門家の視点** から厳しくレビューを行ってください。

各レビュアーは独立して問題を指摘し、重大度を **[MUST FIX] / [SHOULD FIX] / [OPTIONAL]** で分類してください。

### レビュアー 1: 厳格なシニアアプリエンジニア
重点:
- アーキテクチャ違反（presentation / application / domain / data のレイヤー境界逸脱）
- 不要な依存関係の追加
- パフォーマンス問題（不必要な再ビルド、メモリリーク、重い処理のメインスレッド実行）
- 既存パターンとの一貫性
- SOLID 原則違反

### レビュアー 2: 品質重視の QA エンジニア
重点:
- エッジケースの考慮漏れ（null、空リスト、境界値、ネットワークエラー）
- バリデーション漏れ
- エラーハンドリングの不足や不適切なキャッチ
- テストカバレッジの不足（テストすべきケースが書かれていないか）
- 状態遷移の抜け漏れ

### レビュアー 3: 厳格なセキュリティエンジニア
重点:
- 認証・認可の不備
- データ漏洩リスク（ログへの機密情報出力、安全でないストレージ使用）
- インジェクション脆弱性（URL 組み立て、HTML/JS インジェクション）
- 安全でない通信（HTTP の使用、証明書検証の欠如）
- ハードコードされたシークレットや認証情報

### レビュアー 4: UI/UX デザイナー & アクセシビリティ専門家
重点:
- ユーザー体験の一貫性（既存画面との操作感のずれ）
- ローディング・エラー・空状態の適切な UI 表示
- アクセシビリティ対応（Semantics、コントラスト、タッチターゲットサイズ）
- レスポンシブ対応（画面サイズの考慮）
- 国際化・ローカライゼーションの考慮

### レビュアー 5: 新人開発者
重点:
- コードの可読性（変数名・関数名は意味が分かるか）
- 処理の流れが追いやすいか
- マジックナンバーや不明瞭な定数がないか
- コメントが必要な箇所に欠けていないか
- 初見で理解できない複雑なロジックがないか

### レビュアー 6: テックリード（総合判断）
重点:
- 変更の scope は適切か（スコープクリープがないか）
- 将来の保守性への影響
- 他の機能への副作用リスク
- 技術的負債の増加
- チーム全体への影響（コーディング規約との整合性）

## ステップ 4: 修正の実施

MUST FIX の指摘がある場合は、修正を行い、ステップ 1 の品質チェックを再実行してください。
SHOULD FIX についても、修正が容易であれば対応してください。

すべての MUST FIX が解消されるまで繰り返してください。
