## 視点1: ライトユーザー（初めてアプリを使う視聴者）

> 「ニコ生のコメントを見たいだけなんだけど、このアプリどう使うの？」

| 不足している機能 | なぜ必要か | 現状 |
|---|---|---|
| **読み上げ機能** | アプリの核となる機能。設定画面にUIがあるのにオン/オフしても何も起きない | 設定UIのみ存在。エンジン本体が未実装 |
| **放送を探す手段** | lv番号を知っている人しか使えない。初心者はlv番号がそもそも分からない | lv番号の手入力のみ |
| **初回起動時のガイド** | 何をすればよいか分からない。ログインが必要なのか、lv番号はどこで調べるのか | ガイドやチュートリアルなし |
| **フォロー中の放送一覧** | ログイン済みなら、フォローしている配信者の放送をワンタップで開きたい | API実装済みだがUI統合が未完成 |

### 改善提案

- 読み上げ機能の実装が最優先（アプリの存在意義に直結）
- SelectScreenに「放送の探し方」のヒントテキストを追加
- フォロー放送一覧のUI完成で、lv番号を知らなくても使えるようにする

## 補足: 統計表示機能の設計方針

### コメント統計のステータスバー表示

**判断: オプトイン（既定OFF）で実装する**

CommentScreen のステータスバーに統計情報を表示する。配信者にも視聴者にも有用だが、
小規模配信者へのプレッシャーや情報過多を避けるため、すべて既定OFFとする。

#### 表示場所

CommentScreen のステータスバー（Wi-Fiアイコン・lv・最終受信時刻と同じ領域）に追加表示する。

#### 設定の階層構造

```
設定画面
└─ コメント表示セクション
   └─ 統計表示（トグル）← 親スイッチ。OFF なら以下すべて非表示
      ├─ リスナー数・コメント数（トグル）
      └─ 5分間アクティブユーザー数（トグル）
```

| 設定項目 | 既定値 | 説明 |
|---|---|---|
| 統計表示 | OFF | 親スイッチ。OFFなら子の設定に関わらず何も表示しない |
| リスナー数・コメント数 | ON | 親がONのとき、累計リスナー数と累計コメント数を表示 |
| 5分間アクティブユーザー数 | ON | 親がONのとき、直近5分間のユニークコメントユーザー数を表示 |

- 親スイッチがOFFの間、子の設定UIはグレーアウト（無効化）する
- 子の既定はいずれもON（親をONにした時点で全項目が表示される）

#### 表示イメージ

```
統計OFF（既定）:
┌─────────────────────────────────────┐
│ 📶 lv345678901  最終受信 12:34:56   │
└─────────────────────────────────────┘

統計ON / リスナー・コメントON / アクティブON:
┌─────────────────────────────────────┐
│ 📶 lv345678901  最終受信 12:34:56   │
│ 👤 42  💬 386  🔥 8 (5分)          │
└─────────────────────────────────────┘

統計ON / リスナー・コメントON / アクティブOFF:
```

#### データソース

| 指標 | 取得方法 | 備考 |
|---|---|---|
| リスナー数 | NDGR statistics メッセージの `viewers` | APIから取得。アプリ側でカウントしない |
| コメント数 | `TimelineStore` の累計追加数 | アプリが受信した分のみ（途中参加では過去分含む） |
| 5分間アクティブ数 | `TimelineStore` の直近5分間の `userId` ユニーク数 | アプリ側で算出。匿名(`a:xxx`)も1ユーザーとしてカウント |

#### リスク認識（記録として残す）

以下は設計時に検討したリスク。オプトイン（既定OFF）の採用で緩和している。

1. **小規模配信者へのプレッシャー**: 数字が小さいとモチベーション低下の可能性 → 既定OFFで自発的に有効化した人のみ見る
2. **計測精度**: リスナー数はAPI依存、アクティブ数はアプリ受信分のみで過小カウントの可能性 → 厳密な数値ではないことをUIで示唆しない（数字のみ表示し「正確」とは言わない）
3. **ステータスバーの情報過多**: 統計をすべてONにすると表示要素が増える → 2段表示で既存情報と分離
