## 1. 本書の目的と範囲

本書は統合仕様のUI関連要件を実装可能な粒度に落とし込んだものである。
統合仕様のセクション4（UI仕様）を中心に、セクション5（アーキテクチャ）・6（状態機械）・10（読み上げ）・12（ロギング）・13（エラー）・14（受け入れ基準）からUI動作に影響する要件を抽出・統合した。

統合仕様に記載がなく本書で推奨・提案している箇所は **【推奨】** と明記する。
統合仕様との矛盾や曖昧点は **【要確認】** と明記し、セクション12（未確定事項・オープンクエスチョン）にまとめる。

### 統合仕様との関係・優先ルール

| ドキュメント | 正源とする範囲 |
|---|---|
| `Integrated_Requirements_and_Specification.md`（統合仕様） | 何をするか（要件・機能・接続仕様） |
| 本書（UI仕様） | どう見せるか（画面構成・ウィジェット・インタラクション詳細） |

- 同一項目で両ドキュメントの記述が食い違う場合は、**統合仕様を優先する**。
- 本書で **【推奨】** として追加した項目が後日確定した場合は、統合仕様にも反映するか、本書の該当箇所から **【推奨】** タグを外して確定済みとする。
- 本書の変更が統合仕様の要件に影響する場合は、統合仕様も合わせて更新する。

## 2. 画面構成

### 2.1 画面数

v1.2 では以下の3画面構成とする。

| 画面 | 役割 |
|------|------|
| 接続先選択画面（SelectScreen） | 放送ID/URLを入力して接続先を決める。将来的にはログイン後のフォローリストからも選択できるようにする |
| コメント閲覧画面（CommentScreen） | 接続中の放送のコメント一覧を表示する |
| 設定画面（SettingsScreen） | 読み上げエンジン・各種パラメータを設定する |

- 接続先選択画面 → 接続開始 → コメント閲覧画面、という画面遷移を基本とする
- 設定画面はコメント閲覧画面のオーバーフローメニュー（⋮）から開く

### 2.2 接続先選択画面（SelectScreen）のブロック構成

| # | ブロック | 役割 |
|---|---------|------|
| A | AppBar | アプリ名「comerune」を表示 |
| B | 入力エリア | 放送ID/URL入力 + 接続ボタン |

将来拡張: ログイン後にフォロー中の放送者一覧を表示し、タップで接続先を選択できるようにする（v1.2 非ゴール）。

### 2.3 コメント閲覧画面（CommentScreen）のブロック構成

| # | ブロック | 役割 |
|---|---------|------|
| A | AppBar | 接続中の放送情報（放送者名または lv）を表示。右端にオーバーフローメニュー（⋮）を配置し、設定画面への導線とする |
| B | ステータスバー | Wi-Fiアイコン + 通常表示項目（lv・最終受信・再接続回数・直近エラー）。方式・フェーズはデバッグモード時のみ追加表示 |
| C | コメント一覧 | ListView。画面の残り領域すべてを占有する |
| D | 操作ボタン | 画面下部に固定配置。接続中は「接続停止」ボタン（停止で SelectScreen に戻る）。ENDED / FAILED 時は「再接続」ボタン（同一 lv で再接続）を表示する |

## 3. 入力エリア（ブロックB）

### 3.1 テキスト入力欄

| 項目 | 仕様 | 根拠 |
|------|------|------|
| 入力内容 | 放送ID（`lv345678901`）またはニコ生URL | 統合仕様 §4.2 |
| lv抽出ロジック | 正規表現 `lv\d+` で最初にマッチした文字列を採用 | 統合仕様 §4.2 |
| 入力欄の表示 | ユーザーが入力した文字列をそのまま保持する。抽出・除去はバックエンド側で行い、入力欄の見た目は変えない | 統合仕様 §4.2「それ以外は除去」はlvParser側の処理であり、入力欄の書き換えとは区別する |
| プレースホルダー | **【推奨】** `lv番号またはURLを入力` | 統合仕様に指定なし |
| Enterキー | IMEの送信/完了アクションで接続開始（接続ボタンと同じ処理） | 統合仕様 §4.2 |
| キーボード種別 | **【推奨】** `TextInputType.url`（URL入力に適したキーボード） | 統合仕様に指定なし |
| Enter後のキーボード | **【推奨】** 自動でキーボードを閉じる（コメント一覧の表示領域を確保するため） | 統合仕様に指定なし |
| 接続中の入力欄 | 接続中（CONNECTING〜STREAMING〜RECONNECTING）は disabled にする。停止後に編集可能に戻る |

### 3.2 入力値バリデーション

| ケース | 動作 |
|--------|------|
| `lv\d+` マッチあり | 最初のマッチを抽出し、デバッグ欄に反映。接続処理に渡す |
| `lv\d+` マッチなし | `LV_PARSE_FAILED` をデバッグ欄に表示。接続処理は開始しない |
| 入力欄が空 | **【推奨】** 接続ボタンを無効化（グレーアウト）。Enter押下でも何もしない |
| 複数の lv がマッチ | **【推奨】** 最初のマッチを採用する。ユーザーへの通知は不要 |

### 3.3 ペースト操作

- URLをペーストした場合、入力欄にはペーストされた文字列がそのまま表示される
- 統合仕様 §14「URL貼り付けで lv が抽出される」は、接続開始時に抽出が行われることを意味する
- ペースト時点で自動接続はしない（ユーザーが接続ボタンまたはEnterを押すまで待つ）

## 4. 操作ボタン（ブロックB内）

### 4.1 接続ボタン

| 接続状態 | ボタン状態 | 押下時の動作 |
|---------|-----------|-------------|
| IDLE | 有効 | 入力欄のlvを抽出し、接続を開始する |
| STOPPED | 有効 | 同上 |
| FAILED | 有効 | 同上（再試行） |
| ENDED | 有効 | 同上（同一lvへの再接続） |
| CONNECTING_SESSION_WS | **無効** | 何もしない |
| RESOLVING_ENDPOINTS | **無効** | 何もしない |
| STREAMING_NDGR | **無効** | 何もしない |
| STREAMING_LEGACY | **無効** | 何もしない |
| RECONNECTING | **無効** | 何もしない |

- 「既に接続中の場合は無効化」を採用（統合仕様 §4.3「無効化推奨」に従う）
- 接続開始時にlv抽出に失敗した場合、状態は IDLE のまま保ち、`LV_PARSE_FAILED` をデバッグ欄に表示する

### 4.2 接続停止ボタン

| 接続状態 | ボタン状態 | 押下時の動作 |
|---------|-----------|-------------|
| IDLE | **無効** | 何もしない |
| STOPPED | **無効** | 何もしない |
| FAILED | **無効** | 何もしない |
| ENDED | **無効** | 何もしない（放送終了済みのため停止操作は不要） |
| CONNECTING_SESSION_WS | 有効 | 全停止し STOPPED へ遷移 |
| RESOLVING_ENDPOINTS | 有効 | 全停止し STOPPED へ遷移 |
| STREAMING_NDGR | 有効 | 全停止し STOPPED へ遷移 |
| STREAMING_LEGACY | 有効 | 全停止し STOPPED へ遷移 |
| RECONNECTING | 有効 | 全停止し STOPPED へ遷移 |

停止対象（統合仕様 §4.3）:
1. 入口WS（Session WS）
2. コメント接続（NDGR HTTP streaming / legacy WS）
3. 読み上げキュー（再生中の音声も停止）

### 4.3 再接続ボタン（CommentScreen・ENDED / FAILED 時）

ENDED / FAILED では CommentScreen に留まり、画面下部のボタンが「再接続」に切り替わる。

| 接続状態 | ボタン状態 | 押下時の動作 |
|---------|-----------|-------------|
| ENDED | 有効 | 同一 lv で再接続を開始する（IDLE → CONNECTING_SESSION_WS） |
| FAILED | 有効 | 同一 lv で再接続を開始する（IDLE → CONNECTING_SESSION_WS） |
| その他 | 表示しない（停止ボタンを表示） | - |

- 再接続成功でコメント流入が再開した場合、コメント一覧は前回分を保持したまま新着が追加される
- ユーザーが SelectScreen に戻りたい場合は、Android バックボタンまたは AppBar の戻る矢印を使う

### 4.4 ボタンの視覚的状態

| 状態 | 表現 |
|------|------|
| 有効 | 通常の MaterialButton の外観 |
| 無効 | グレーアウト。タップしてもフィードバックを返さない |

## 5. ステータスエリア（ブロックC）

### 5.1 Wi-Fiアイコン

Material Icons の `Icons.wifi` を使用する。

| アイコン色 | 対応状態 | 根拠 |
|-----------|---------|------|
| 緑（`Colors.green`） | CONNECTING_SESSION_WS / RESOLVING_ENDPOINTS / STREAMING_NDGR / STREAMING_LEGACY | 統合仕様 §6.3 |
| 緑（`Colors.green`） | RECONNECTING | 統合仕様 §4.4「稼働に向けた接続試行中」に該当するため緑とする |
| 赤（`Colors.red`） | IDLE / STOPPED / FAILED / ENDED | 統合仕様 §6.3 |

### 5.2 ステータスバーの表示項目

通常モードとデバッグモードで表示内容を切り分ける。

#### 通常モード（常時表示）

| フィールド | 表示内容 | 未取得時の表示 |
|-----------|---------|-------------|
| lv | 抽出した放送ID | `-` |
| 最終受信時刻 | コメントまたはWSメッセージの最終受信時刻（`HH:mm:ss`） | `-` |
| 再接続回数 | 接続開始後の累計再接続回数（整数） | `0` |
| 直近エラー | 直近のエラーコード（例: `NDGR_STREAM_FAILED`）または短文メッセージ | `-` |

#### デバッグモード時の追加表示

| フィールド | 表示内容 | 未取得時の表示 |
|-----------|---------|-------------|
| 接続方式 | `NDGR` / `legacy` | `-` |
| 接続フェーズ | 状態機械の現在状態名 | `IDLE` |

- デバッグモードの ON/OFF は設定画面のトグルで切り替える
- **【推奨】** フォントサイズは 12sp。コメント一覧の領域を圧迫しないよう、コンパクトに表示する
- **【推奨】** 各フィールドは `key: value` 形式で1行に並べる

### 5.3 デバッグ情報の更新タイミング

| イベント | 更新されるフィールド |
|---------|-------------------|
| lv抽出成功 | lv |
| 接続方式判別完了 | 接続方式 |
| 状態遷移 | 接続フェーズ |
| コメント/WS受信 | 最終受信時刻 |
| 再接続発生 | 再接続回数（+1） |
| エラー発生 | 直近エラー |
| 接続停止（STOPPED） | 接続フェーズのみ更新。他のフィールドは直前の値を保持（診断に有用なため） |
| 新規接続開始（IDLE → CONNECTING） | 全フィールドリセット（lv以外は初期値に戻す） |

## 6. コメント一覧（ブロックD）

### 6.1 基本表示仕様

| 項目 | 仕様 | 根拠 |
|------|------|------|
| 並び順 | 古い順（上が古い、下が新しい） | 統合仕様 §4.5 |
| ウィジェット | `ListView.builder`（パフォーマンスのため） | - |
| 占有領域 | ブロックA〜Cを除いた画面の残り全域 | - |

### 6.2 コメント行の表示内容

各行に表示する情報:

| 要素 | 内容 | 表示例 |
|------|------|--------|
| タイムスタンプ | `HH:mm:ss` 形式。サーバ時刻優先、取得不可なら受信時刻 | `12:34:50` |
| ユーザーID | userId が取得できた場合に表示。取得不可なら省略 | `user123` |
| コメント本文 | `content` フィールド | `こんにちは` |

行フォーマット例:
```
12:30:01  user123  こんにちは
12:30:03           888888
12:30:05  user456  わこつ
```

- userId が空の行は、タイムスタンプの後に空白を詰めてコメント本文を表示する
- **【推奨】** コメント本文のフォントサイズは 14sp 以上（可読性確保）

### 6.3 コメント種別（AppMessage.type）の表示

統合仕様 §5.2, §8.4 では type として `chat` / `operator` / `notification` / `gift` / `nicoad` が定義されている。

| type | v1.2での表示方針 | 根拠 |
|------|----------------|------|
| `chat` | 必須表示。標準の行スタイル | 統合仕様 §8.4「最低限 chat の表示を必須」 |
| `operator` | 表示する。**背景色で区別する**（例: 薄い黄色の背景）。運営/配信者コメントであることが視覚的にわかるようにする | 統合仕様 §5.2 |
| `notification` | 表示する。**背景色で区別する**（例: 薄い青色の背景）。通知コメントであることが視覚的にわかるようにする | 統合仕様 §5.2 |
| `gift` / `nicoad` | v1.2 では非表示（将来拡張） | - |

### 6.4 自動スクロール

| 状況 | 動作 | 根拠 |
|------|------|------|
| ユーザーがスクロール操作をしていない | 新着コメント受信時に最下部へ自動スクロール | 統合仕様 §4.5 |
| ユーザーが上方向にスクロールした | 自動スクロールを停止する | 統合仕様 §4.5「推奨」 |
| ユーザーが最下部まで戻った | 自動スクロールを再開する | - |

自動スクロール停止の判定方法:

- **【推奨】** ScrollController の position を監視し、最下部（`maxScrollExtent`）から一定距離（例: 50 logical pixels）以上離れたら「ユーザーが手動スクロール中」と判定する
- **【推奨】** 自動スクロール停止中に「↓ 新着あり」のような浮動ボタン（FAB）を表示し、タップで最下部に移動+自動スクロール再開とする。この FAB は統合仕様に記載がないため、実装判断に委ねる

### 6.5 タップ操作

- v1.2 ではコメント行のタップ操作に読み上げ機能を割り当てない
- 将来拡張として、コメント詳細表示やコピーなどの操作を検討する

### 6.6 リングバッファとUIの関係

統合仕様 §5.1 では TimelineStore が「リングバッファ」でコメントを保持すると記載されている。

- **【推奨】** リングバッファの上限に達した場合、古いコメントがUIの一覧からも消える。ユーザーが上方にスクロールしている最中に上部の行が消えることになるため、スクロール位置の維持に注意が必要
- リングバッファの上限件数は **100件**（統合仕様 §5.1 確定済み）

### 6.7 過去コメント初期ロード

NDGR 接続時、直近100件の過去コメントがロードされる（統合仕様 §8.2）。

- **【推奨】** 過去コメントのロード中にローディングインジケータを表示するかどうかは実装判断に委ねる。最低限、過去コメントもリアルタイムコメントと同じ行スタイルで表示する（視覚的な区別は v1.2 では不要）

### 6.8 空状態

接続前（IDLE）やコメント未受信時のコメント一覧の表示:

- **【推奨】** 空の ListView を表示する（プレースホルダーメッセージは不要。ステータスエリアで状態がわかるため）

## 7. エラー表示

### 7.1 表示方針（統合仕様 §13.2 ベース）

| エラー種別 | UI上の表現 | 根拠 |
|-----------|-----------|------|
| lv抽出失敗（`LV_PARSE_FAILED`） | デバッグ欄「直近エラー」に表示 + **【推奨】** Snackbar で「放送IDが見つかりません」を表示 | 統合仕様 §13.1 |
| 致命的失敗（→ FAILED 遷移） | デバッグ欄更新 + **【推奨】** Snackbar で原因カテゴリと「接続ボタンで再試行できます」を表示 | 統合仕様 §13.2 |
| 断続的エラー（再接続中） | デバッグ欄の「直近エラー」を上書き更新のみ。Snackbar やダイアログは**出さない** | 統合仕様 §13.2「UIを騒がせずデバッグ欄に記録」 |
| 読み上げ失敗（棒読み/VOICEVOX） | デバッグ欄のみ。ユーザー通知不要 | 統合仕様 §10.2, §10.3「スキップしてキューを詰まらせない」 |

### 7.2 Snackbar の仕様（推奨）

**【推奨】** 統合仕様には通知UIの具体方式の指定がないため、以下を推奨する。

| 項目 | 仕様 |
|------|------|
| 表示位置 | 画面下部（Material の標準 Snackbar） |
| 表示時間 | 4秒で自動消去 |
| 表示内容 | エラーカテゴリの日本語メッセージ |
| アクション | なし（再試行は接続ボタンで行うため） |
| 同時表示 | 最新の1件のみ（上書き） |

### 7.3 エラーコードとユーザー向けメッセージの対応

| エラーコード | Snackbar表示 | FAILED遷移するか |
|-------------|-------------|-----------------|
| `LV_PARSE_FAILED` | 「放送IDが見つかりません」 | しない（IDLE のまま） |
| `SESSION_WS_CONNECT_FAILED` | 「セッション接続に失敗しました」 | 再接続上限超過時のみ |
| `ENDPOINT_RESOLVE_FAILED` | 「コメントサーバーの取得に失敗しました」 | する |
| `NDGR_STREAM_FAILED` | 再接続中は表示なし / 最終失敗時のみ表示 | 再接続上限超過時のみ |
| `LEGACY_WS_FAILED` | 同上 | 同上 |
| `SPEECH_BOUYOMI_FAILED` | 表示なし | しない |
| `SPEECH_VOICEVOX_FAILED` | 表示なし | しない |

## 8. 設定画面 UI

### 8.1 配置方法

別画面（SettingsScreen）として実装する。コメント閲覧画面の AppBar オーバーフローメニュー（⋮）から遷移する。

### 8.2 設定画面への導線

- **【推奨】** AppBar 右端のオーバーフローメニュー（⋮）に「設定」項目を配置
- タップで設定画面に遷移（`Navigator.push`）

- 永続化対象: §8.4 に記載の全設定項目

### 8.7 設定変更時の動作（接続中のケース）

| 設定項目 | 接続中に変更した場合の動作 |
|---------|------------------------|
| 自動読み上げ ON/OFF | 即時反映。OFF にした瞬間から新着コメントの自動読み上げが停止する。再生中の音声は中断しない |
| 読み上げエンジン | 次の読み上げから新エンジンを使用する。再生中の音声は中断しない |
| キュー上限 / 最大遅延 | 即時反映。既にキューに入っている分は新しい上限で再評価する |
| URL省略 / 連投抑制 / NGワード | 次にキューに入るコメントから適用 |
| 棒読みちゃん音声パラメータ | 次の送信から反映 |
| VOICEVOX 音声パラメータ | 次のAPI呼び出しから反映 |
| 過去コメント取得件数 | 次回の接続開始時に反映される（接続中の変更は次の接続に持ち越し） |

### 8.8 エンジン固有設定の表示切替

読み上げエンジンのラジオボタン選択に連動して、エンジン固有の設定セクションを切り替える。

| 選択中のエンジン | 表示するセクション | 非表示にするセクション |
|----------------|-------------------|---------------------|
| 棒読みちゃん | 「棒読みちゃん（音声パラメータ）」 | 「VOICEVOX（音声パラメータ）」 |
| VOICEVOX | 「VOICEVOX（音声パラメータ）」 | 「棒読みちゃん（音声パラメータ）」 |

- ラジオボタンの選択変更時、即座にセクション表示が切り替わる（アニメーション付きで折りたたみ/展開を推奨）
- 非表示中のセクションの設定値は保持される（切り替えても失われない）
- 共通セクション（読み上げキュー、読み上げフィルタ、コメント表示）は常時表示

### 8.9 接続先設定について

- **棒読みちゃん**: ホストは設定画面の棒読みちゃんセクションでユーザーが入力する（§8.4）。ポートは `50001` 固定
- **VOICEVOX**: host / port は一般ユーザーが操作するものではないため、設定画面には配置しない。以下のいずれかの方法で管理する（実装時に選択）:
  - アプリ内の定数として定義し、ビルド時に切り替える
  - 開発者向けの隠し設定（例: デバッグメニュー、SharedPreferences 直接編集）として提供する
  - 既定値: host=`10.0.2.2`（エミュレータ）/ LAN内ホスト（実機）, port=`50021`

## 10. ユーザーフロー

### 10.1 基本フロー: コメント閲覧

```
1. アプリ起動 → SelectScreen 表示
2. 入力欄に lv 番号またはURLを入力（またはペースト）
3. 接続ボタンを押す（またはEnter）
4. → lv が抽出される
5. → CommentScreen に遷移、入口WSに接続開始（Wi-Fiアイコンが緑に変わる）
6. → 接続方式が判別される → デバッグ欄に反映
7. → コメント受信開始 → 一覧に表示される
8. → 新着コメントで自動スクロール
9. 視聴終了 → 停止ボタンを押す
10. → 全接続停止 → SelectScreen に戻る（Wi-Fiアイコンが赤に変わる）
```

### 10.2 フロー: 接続失敗

```
1. SelectScreen で入力欄に不正な文字列を入力
2. 接続ボタンを押す
3. → lv 抽出失敗
4. → Snackbar「放送IDが見つかりません」
5. → 状態は IDLE のまま（SelectScreen に留まる）
```

### 10.3 フロー: 自動再接続

```
1. CommentScreen で STREAMING_NDGR 中に回線断発生
2. → RECONNECTING に遷移（Wi-Fiアイコンは緑のまま、CommentScreen に留まる）
3. → デバッグ欄: エラーコード更新、再接続回数+1
4. → 指数バックオフで再接続試行
5a. 成功 → STREAMING_NDGR に復帰、コメント流入再開（CommentScreen に留まる）
5b. 上限超過 → FAILED に遷移（Wi-Fiアイコンが赤に、CommentScreen に留まる）→ Snackbar表示
```

### 10.4 フロー: 放送終了

```
1. CommentScreen で STREAMING 中にサーバから放送終了イベントを受信
2. → ENDED に遷移（Wi-Fiアイコンが赤に変わる、CommentScreen に留まる）
3. → 全接続停止（入口WS / コメントストリーム / 読み上げキュー）
4. → デバッグ欄に「放送終了」と表示
5. → 自動再接続はしない
6. ユーザーが同一lvで再試行したい場合: CommentScreen 上の接続ボタンを押す → IDLE と同様の接続フローへ
7. ユーザーが別の放送に切り替えたい場合: 戻るボタンで SelectScreen に戻り、新しい lv を入力する
```

### 10.5 フロー: 別の放送に切り替え

```
1. CommentScreen で STREAMING 中に停止ボタンを押す
2. → STOPPED に遷移 → SelectScreen に戻る
3. SelectScreen で入力欄に新しい lv を入力
4. 接続ボタンを押す
5. → CommentScreen に遷移、前回のコメント一覧がクリアされ、新しい接続を開始
```

コメント一覧のクリア方針:
- **同じ lv への再接続**: 前回のコメントを保持する（断線復帰のケースで履歴が消えるのを防ぐ）
- **別の lv への接続**: 前回のコメント一覧をクリアして新規開始する

## 13. 受け入れ基準（UI観点）

統合仕様 §14 の受け入れ基準をUI観点で分解する。

| # | 基準 | UIでの確認方法 |
|---|------|---------------|
| 1 | URL貼り付けで lv が抽出される | URLペースト → 接続 → デバッグ欄の lv フィールドに正しい値が表示される |
| 2 | 接続開始でコメントが流れる | 接続ボタン押下 → コメント一覧に行が追加される |
| 3 | 接続停止で確実に停止する | 停止ボタン押下 → Wi-Fiアイコンが赤に変わる → コメントの追加が止まる |
| 4 | Wi-Fiアイコンが状態に応じて赤/緑で切り替わる | 各状態遷移でアイコン色を目視確認 |
| 5 | 新着で自動スクロールする | コメント流入中に最下部が維持される |
| 6 | ユーザーがスクロール中は自動スクロール停止 | 上方向にスクロール → 新着が来ても位置が動かない → 最下部に戻ると自動スクロール再開 |
| 7 | 読み上げが動作する（棒読みちゃん） | 設定で棒読みちゃんを選択 → コメント受信時に棒読みちゃんから音が鳴る |
| 8 | 読み上げが動作する（VOICEVOX） | 設定で VOICEVOX を選択 → コメント受信時にアプリから音が鳴る |
| 9 | 瞬断後に自動復帰する | ネットワーク断 → 30秒以内にコメント流入が再開する |
| 10 | デバッグ情報が揃っている | ステータスバーの通常表示4フィールドが更新される。デバッグモード ON 時は方式・フェーズも更新される |

## 14. テスト観点（UI/Widget テスト）

| テスト対象 | テスト内容 |
|-----------|-----------|
| 入力欄バリデーション | 空入力・不正入力で接続が開始されないこと |
| lv 抽出 | URL/lv番号の各パターンで正しく抽出されること |
| ボタン有効/無効 | 各状態で接続/停止ボタンの有効/無効が正しく切り替わること |
| Wi-Fi アイコン色 | 各状態で緑/赤が正しく切り替わること |
| デバッグ情報更新 | 各イベント発生時に対応フィールドが更新されること |
| コメント行表示 | タイムスタンプ・userId・content が正しくレンダリングされること |
| 自動スクロール | 新着追加で最下部に移動すること |
| 自動スクロール停止 | ユーザースクロール中は新着で位置が動かないこと |
| エラー表示 | FAILED 遷移時に Snackbar が表示されること |
| 停止動作 | 停止ボタンで状態が STOPPED になり、UIが正しく更新されること |
| 設定画面遷移 | オーバーフローメニュー → 設定画面が表示される → 戻るボタンでメイン画面に戻ること |
| 自動読み上げ切替 | Switch を ON にすると新着コメントが読み上げられる。OFF にすると止まること |
| エンジン切替 | ラジオボタンで切り替えると、次の読み上げが選択されたエンジンで行われること |
| 数値バリデーション | キュー上限・最大遅延等に不正値を入力するとエラーメッセージが出ること |
| NGワード | 正規表現を設定すると、マッチするコメントの読み上げがスキップされること |
| 設定永続化 | 設定変更後にアプリを再起動しても設定値が保持されていること |
| 接続中の設定変更 | 接続中に自動読み上げ ON/OFF を切り替えると即時に反映されること |
