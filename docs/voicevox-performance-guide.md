# 読み上げ機能の動作要件

comeruneの読み上げ機能は、[VOICEVOX Core](https://github.com/VOICEVOX/voicevox_core) を使い、端末の中だけで音声合成を行います。サーバーへの通信は不要で、オフラインでも読み上げできます。

このページでは、読み上げ機能を快適に使うために知っておいていただきたいことをまとめています。

---

## しくみ

読み上げ機能は、コメントのテキストを端末内のニューラルネットワーク（ONNX Runtime）で計算し、音声データに変換しています。この計算は端末のCPUを使って行われます。

```
コメント到着 → テキスト整形 → 音声合成（ニューラルネットワーク計算） → 再生
```

音声合成のステップで端末のCPUを使うため、ここが処理時間のほとんどを占めます。

---

## 初回セットアップ

読み上げ機能を初めて使うとき、音声データ（音声モデルと辞書データ）のダウンロードが必要です。

- **ダウンロードサイズ**: 約160MB
- **Wi-Fi環境での実行を推奨します**
- ダウンロード後は端末のストレージに約160MBの空き容量を使用します
- 一度ダウンロードすれば、以降はオフラインで利用できます

---

## 端末の性能と読み上げ速度

音声合成は端末内でニューラルネットワークの計算を行うため、端末のCPU性能によって読み上げが始まるまでの時間が変わります。

**どの端末でも読み上げ機能は利用できます。** ただし、古い端末や処理能力の低い端末では、コメントが投稿されてから読み上げが始まるまでに時間がかかる場合があります。

### 性能の目安

以下は端末のCPU性能ごとの目安です。Antutuベンチマーク（v10）の総合スコアと代表的なCPU型番を参考にしてください。

> **注意**: この目安はニューラルネットワーク推論の一般的な性能傾向に基づくものであり、comeruneでの実測値ではありません。実際の応答速度はモデルや端末の状態によって変わります。

| 体感 | Antutu v10 総合スコア | 代表的なCPU |
|---|---|---|
| 快適に読み上げできる | 約40万点以上 | Snapdragon 870 / 888 / 8 Gen 1〜3, Dimensity 8100〜9300, Google Tensor / Tensor G2〜G4, Exynos 2100〜2400 |
| 利用できるが、やや待ち時間がある | 約20万〜40万点 | Snapdragon 695 / 765G / 780G, Dimensity 700 / 800, Helio G99, Exynos 1280 |
| 利用できるが、遅延が大きい場合がある | 約20万点未満 | Snapdragon 660 / 670 / 680, Helio P60 / G80, Exynos 7904 |

スコアが低い端末でも読み上げ機能自体は動作しますが、コメントが集中するとキューが溜まり、読み上げがリアルタイムのコメントの流れに追いつけなくなることがあります。

> 上の目安はまだ実測データが少ない状態です。「この端末で快適に使えた」「この端末では遅かった」といった体験談を [GitHub Issues](https://github.com/sahya/comerune/issues) でお寄せいただけると、目安の精度向上に役立ちます。

### 読み上げが遅くなる場合

以下のような状況では、CPUの処理能力が他の作業に使われるため、読み上げの応答が遅くなることがあります。

- **動画のデコード処理との競合** — 端末で動画を再生しながらコメントを読み上げる場合、動画のデコード処理にCPUが使われるため、音声合成に回せる処理能力が減り、読み上げが遅くなることがあります
- **ライブ配信のエンコード処理との競合** — 端末でライブ配信を行いながらコメントを読み上げる場合も同様に、映像のエンコード処理がCPUを消費するため、読み上げの応答が遅くなることがあります
- **端末の発熱によるクロックダウン** — 長時間の利用や高負荷な処理が続くと、端末が発熱を抑えるためにCPUの速度を落とすことがあり、結果として読み上げも遅くなります
- **バックグラウンドアプリの影響** — 他のアプリがバックグラウンドで重い処理を行っている場合にも影響を受けます

### comeruneが行っている工夫

読み上げが遅れてもコメントが溜まりすぎないよう、以下の仕組みを入れています。

- コメントの文字数を制限し、1件あたりの合成時間を短く保つ
- 同じ内容の連投や記号の連打を自動で間引く
- 再生中に次のコメントの合成を並行して行い、待ち時間を短縮する
- コメントが溜まりすぎた場合は自動で間引く（最大20件まで保持）

## 対応端末

- **OS**: Android
- **アーキテクチャ**: arm64-v8a（現行のほぼすべてのAndroid端末が該当します）

---

## フォーク・改変する方へ

読み上げ機能のパラメータを変更する場合は、以下の点にご注意ください。

| パラメータ | 初期値 | 変更時の影響 |
|---|---|---|
| 最大読み上げ文字数 | 50文字 | 大きくすると1件あたりの合成時間が増加します |
| 最大キュー件数 | 20件 | 大きくするとメモリ消費が増えます |
| 重複抑止時間 | 5秒 | 短くすると同じ内容の読み上げが増えます |

音声合成はCPUバウンドな処理です。パラメータを緩くすると、特に性能の低い端末で読み上げがコメントの流れに追いつけなくなる場合があります。
