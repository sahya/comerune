### Q2: VVM モデルの配布方式

- 仕様では `assets` 同梱を想定しているが、VVM はサイズが大きくアプリサイズに影響する
- **確認事項**: assets 同梱か、初回ダウンロードか

- **確認事項**: 利用規約の確認とアプリへの組み込み可否
- **影響**: リリース可否に直結

### Q4: 初期話者 ID の確定

### Q5: NGワード初期リストの有無

- **確認事項**: 初期リストを空で開始してよいか。提供するリストがあるか
- **影響**: テストケースの設計

### Q6: 絵文字判定の厳密さ

- 「単独絵文字のみ → スキップ」「文中の絵文字 → 削除または『えもじ』に置換」とあるが、どちらにするか未確定
- **確認事項**: 文中絵文字は「削除」と「えもじ置換」のどちらか

### Q7: 顔文字の定義範囲

- 「複雑な顔文字 → 削除」とあるが、何が「複雑な顔文字」かの定義が曖昧
- **確認事項**: 顔文字判定のルールまたはパターン集はあるか
- **影響**: 正規表現の設計
- **Assumption**: 初期版は ASCII 顔文字の基本パターンのみ対象とする

### Q8: キューが満杯時の挙動の優先順

- 仕様では「priority の低いものから削除」とあるが、priority 計算ルールは `isOwner` のみ
- **確認事項**: priority は isOwner (10 vs 0) のみで十分か。score フィールドは priority に反映するか
- **影響**: キューの eviction ロジック
- **Assumption**: 初期版は isOwner のみ使い、score は将来拡張とする

### Q9: Audio Focus の初期挙動

- 「初期版ではまず単純停止でも可」とあるが、「停止」の定義が曖昧
- **確認事項**: フォーカス喪失時は「現在のコメント再生を停止してキュー保持」か「全停止」か
- **影響**: WavPlayer の stop 実装

### Q10: Channel 名のパッケージ名

- 仕様では `jp.example.comment_speech` を使用しているが、これは仮のパッケージ名
- **確認事項**: 実際のパッケージ名/Channel 名
- **影響**: Plugin 登録、Channel 定義

### Q11: エラー時の再初期化ポリシー

- 「エラー継続時のみエンジン再初期化を試行」とあるが、「継続」の閾値は未定義
- **確認事項**: 何回連続失敗で再初期化を試みるか
- **影響**: SpeechController のリカバリロジック
- **Assumption**: 3回連続失敗で再初期化を1回試行する

### Q12: 辞書置換ルールの適用順序

- 仕様の推奨変換表と辞書置換ルールの両方が存在する
- **確認事項**: 推奨変換表（記号圧縮）と辞書置換はどちらが先に適用されるか
- **影響**: 整形結果が変わる可能性がある
- **Assumption**: 記号圧縮 → 辞書置換の順で適用する（仕様の掲載順に従う）

### Q13: TTS 合成方式の選択

- C API には2つの方式がある:
  - **方式1**: TTS 一発呼び出し（単純、初期版向き）
  - **方式2**: `create_audio_query` → パラメータ編集 → synthesis（柔軟、将来向き）
- 0.16 系の設計思想は `create_audio_query` ベース（CHANGELOG で Python API の `audio_query` → `create_audio_query` 改名あり）
- **確認事項**: 初期版は方式1（一発 TTS）でよいか
- **影響**: JNI 層の複雑さ、将来のパラメータ制御の柔軟性
- **Assumption**: 初期版は方式1で実装する。方式2への移行は将来対応

### Q14: speakerId と styleId のマッピング

- VOICEVOX 0.16 系で `VoiceModelId` や style 周りの扱いに変更が入っている
- Releases に `style_id_to_model_inner_id` 変更や VVM に UUID を振る変更がある
- **確認事項**: Kotlin 側の `speakerId` を JNI 内でそのまま style id と見なしてよいか
- **影響**: 複数話者対応時の内部設計
- **Assumption**: 初期版は1話者固定。`speakerId` は実質 style id 固定値として扱う

### Q15: VVM の製品版と sample.vvm の区別

- Releases に「自分でビルドした場合は製品版VVMが読めないことがわかるようにした」という記述がある
- sample.vvm のデプロイが 0.16 preview で中止された
- **確認事項**: 使用する VVM は製品版か、どの話者の VVM を使うか
- **影響**: VVM ファイルの入手方法、テスト可否

## 仕様内の矛盾・注意点

### N1: symbolOnlyRegex にリスト文字が含まれる

- スケルトンコードの `symbolOnlyRegex` に `w` `8` `草` が含まれているが、記号圧縮で「わら」「はくしゅ」「くさ」に変換される。変換後に symbol_only 判定が走ると、変換済みテキストが不当にスキップされる可能性がある
- **対応**: スキップ判定は記号圧縮の前に行うか、変換後のテキストには symbol_only を適用しない

### N2: キュー満杯時に「低優先度から削除」だが実装は「拒否」

- 仕様 Section 4.8 では「あふれた場合は古い低優先度コメントを破棄」とあるが、スケルトンの `InMemorySpeechQueueManager.offer()` は単に `QueueOfferResult(false, "queue_full")` を返す
- **対応**: 仕様どおり eviction ロジックを実装するか、初期版は拒否のままで後から改善するか確認

### N3: 合成失敗後の state 遷移

- 仕様 Section 8 の注意点にもあるとおり、合成失敗で永続的に ERROR になると復帰できない
- **対応**: 一時的失敗は READY に戻す設計を採用する（仕様の推奨に従う）
