# 未確定事項・仕様上の曖昧さ

> **2026-03-28 オーナー決定**: 全項目を推奨案で確定。以下に決定内容を記載。

## 確定済み項目

### Q1: VOICEVOX Core バージョン → `0.16.2` で確定

- **決定**: `0.16.2` に固定する
- ヘッダ (.h) と .so は同一 ZIP 由来にする。混ぜない
- API 変更リスクは JNI 境界を固定して閉じ込める

### Q2: VVM モデルの配布方式 → assets 同梱

- **決定**: 初期版は `assets` に同梱する
- アプリサイズが問題になった場合は将来的に初回ダウンロード方式を検討

### Q3: VVM モデルのライセンス → #40 で確認

- **決定**: #40（人間作業）の中で利用規約を確認してから assets に配置する
- MIT なのは voicevox_core 本体のみ。VVM は別途確認が必要

### Q4: 初期話者 ID → `speakerId: 0` で固定

- **決定**: 初期版は `speakerId: 0` の1話者固定
- 複数話者対応は将来拡張

### Q5: NGワード初期リスト → 空リストで開始

- **決定**: 初期リストは空 (`emptyList()`)
- ユーザーが設定画面から追加する前提

### Q6: 絵文字判定 → 文中絵文字は「削除」

- **決定**: 文中の絵文字は削除する（「えもじ」置換はしない）
- 単独絵文字のみ → スキップ

### Q7: 顔文字の定義範囲 → ASCII 基本パターンのみ

- **決定**: 初期版は ASCII 顔文字の基本パターンのみ対象
- 例: `(;∀;)`, `(´・ω・`)` 等の典型的なもの
- 網羅は目指さない。誤判定より見逃しを許容する

### Q8: キュー満杯時 → 初期版は単純拒否、eviction なし

- **決定**: キュー満杯時は新規コメントを拒否 (`queue_full`)
- priority による eviction は将来拡張
- priority は `isOwner` (10 vs 0) のみ使用。`score` は将来対応

### Q9: Audio Focus 喪失時 → 現在のコメント停止、キュー保持

- **決定**: フォーカス喪失時は現在再生中のコメントを停止し、キューは保持する
- 自動再開はしない（次のコメントは手動 start で処理）

### Q10: Channel 名 → アプリのパッケージ名に合わせる

- **決定**: 実装時にアプリの `applicationId` に合わせて設定する
- 仮: `jp.example.comment_speech` → 実装時に確定

### Q11: エラー時の再初期化 → 3回連続失敗で再初期化試行

- **決定**: 合成が3回連続で失敗した場合、エンジンの `release()` → `initialize()` を1回試行する
- 再初期化も失敗した場合はエラー状態のまま。ユーザーに通知

### Q12: 辞書置換の適用順序 → 記号圧縮 → 辞書置換

- **決定**: 仕様の掲載順に従い、記号圧縮が先、辞書置換が後
- NGワード判定は整形前（原文に対して）

### Q13: TTS 合成方式 → 方式1（一発 TTS）

- **決定**: 初期版は TTS 一発呼び出し方式
- 方式2 (`create_audio_query` ベース) への移行は将来対応
- 理由: 短文コメント読み上げ用途では単純な方が安定する

### Q14: speakerId の扱い → そのまま style id として使用

- **決定**: Kotlin の `speakerId` を JNI 内でそのまま style id として渡す
- 初期版は1話者固定なので内部マッピングは不要
- 複数話者対応時に必要なら mapping を追加

### Q15: VVM → 製品版を使用、#40 で入手・配置

- **決定**: 製品版 VVM を使用する
- 具体的な話者・VVM ファイルは #40（人間作業）で選定・配置

## 仕様内の矛盾への対応（確定）

### N1: symbolOnlyRegex の適用タイミング → 記号圧縮の前に判定

- **決定**: symbol_only スキップ判定は記号圧縮の**前**に実行する
- 理由: 変換後の「わら」「くさ」等が不当にスキップされるのを防ぐ

### N2: キュー満杯時 → 初期版は単純拒否

- **決定**: Q8 と同じ。初期版は拒否。eviction は将来対応

### N3: 合成失敗後の state → 一時的失敗は READY に戻す

- **決定**: 仕様の推奨に従い、合成の一時的失敗では `READY` に戻す
- 初期化失敗のみ `ERROR` 扱い
