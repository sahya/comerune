# Issue 03: コメント整形 — URL・記号圧縮・絵文字変換

## Goal

コメント内の URL、連続記号、絵文字を読み上げに適した形に変換する。
これにより「wwwww」が延々と読み上げられたり、URLが全文読まれたりする問題を防ぐ。

## Scope

### URL 処理（仕様 Section 3.5.2）

- URL を含むコメント → URL 部分を `"URL省略"` に置換
- URL のみのコメント → スキップ（`skipReason = "url_only"`）
- 正規表現: `https?://[\w/:%#$&?\(\)~.=+\-]+`

### 記号圧縮（仕様 Section 3.5.3）

推奨変換表:

| パターン | 変換後 |
|---|---|
| `w{2,}` (大文字小文字不問) | わら |
| `草{2,}` | くさ |
| `8{3,}` / `８{3,}` | はくしゅ |
| `!{2,}` / `！{2,}` | びっくり |
| `?{2,}` / `？{2,}` | はてな |
| `[ー～〜]{3,}` | のばし |

### 絵文字処理（仕様 Section 3.5.4）

- 単独絵文字のみ → スキップ（`skipReason = "emoji_only"`）
- 文中の絵文字 → 削除
- 複雑な顔文字 → 削除

**Assumption**: 文中絵文字は「削除」で実装する（未確定事項 Q6）。顔文字は基本的な ASCII パターンのみ対象（Q7）。

## Non-scope

- 辞書置換ルール（Issue 04）
- NGワード（Issue 04）
- 文字数制限（Issue 04）
- 絵文字の「えもじ」置換対応（将来拡張）
- 複雑な顔文字辞書

## Dependencies

- Issue 01（データモデル）
- Issue 02（CommentNormalizer 骨格。この Issue で変換ルールを追加する）

## Acceptance Criteria

1. `"https://example.com/test"` → スキップ（URLのみ）
2. `"これ見て https://example.com/test"` → `"これ見て URL省略"`
3. `"wwwww"` → `"わら"`
4. `"草草草"` → `"くさ"`
5. `"888888"` → `"はくしゅ"`
6. `"!!!!!!"` → `"びっくり"`
7. `"?????"` → `"はてな"`
8. `"ーーーー"` → `"のばし"`（前後に空白が入ってもよい）
9. `"😊😊😊"` → スキップ（絵文字のみ）
10. `"ありがとう😊"` → `"ありがとう"`

## Test Expectations

- **単体テスト（必須）**:
  - URL 置換の各パターン（URLのみ、URL混在、URL無し）
  - 記号圧縮の全パターン（変換表の各行）
  - 閾値未満の記号が変換されないこと（例: `"w"` 1個は変換しない）
  - 絵文字のみスキップ
  - 文中絵文字の削除
  - 複合パターン（URL + 記号 + テキスト混在）

## AI 実装適性

- **AI 実装に向いている**: 正規表現ベースの変換ロジック。テストケースが仕様に明記されている
- **人間承認ポイント**: 絵文字判定の正規表現の精度（完全一致は難しいため、カバレッジの期待値を合わせる）

## Implementation Notes

- URL 正規表現は仕様提供のものを使う
- 記号圧縮は全角・半角の両方を考慮する（`8` と `８`、`!` と `！` 等）
- 絵文字判定は Unicode カテゴリ `\p{So}` + Surrogate を基本とする
- 変換の適用順序: URL処理 → 記号圧縮 → 絵文字処理（仕様の掲載順）
- 記号圧縮で変換された結果が symbol_only 判定に引っかからないよう注意（N1 参照）
